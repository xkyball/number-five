# OpenCPN chart engine and native boundary

The chart path now uses the complete `s52plib.cpp` with its retained CPU and GLES branches, conditional-symbology dispatch in `s52cnsy.cpp`, original lookup/rule parsing, atlas symbols, patterns, text, sounding and line rendering from OpenCPN `452a60d963b876bddd2f8e5eefe1c814d6e4e39c`. The initial area/solid-line extraction has been removed. All 21 public fixture objects resolve to original S52 lookups; two are excluded by OpenCPN's display rules. This is development validation, not a navigational acceptance certificate.

## Data and rendering

Public S57 `.000` cells with colocated sequential updates pass through the retained S57 reader. The No5 cache driver calls the original OSENC 201 feature, coverage and vector-table writers. It validates the resulting plaintext geometry records before calling original `Osenc::ingest200`. Original S57 objects, triangle geometry, shared edges and connected nodes feed the retained `s57chart::AssembleLineGeometry`, `SetLinePriorities`, feature selection and area association methods.

The first cache policy deliberately rebuilds geometry from the authoritative `.000` on every chart-set open, writes a temporary file and renames it only after validation. It therefore never silently reuses stale source geometry. Plaintext `.senc` and `.S57` inputs are accepted only as structurally valid OSENC 201. Record lengths, known records, allocation counts, geometry/attribute order, finite coordinates, feature IDs and supported attribute types are checked before upstream ingestion. Missing sequential S57 updates fail the open. Persistent reuse and source fingerprints belong to a later cache optimization.

Original `ChartDB::BuildChartStack`, `CheckPositionWithinChart`, `EqualStacks` and ChartStack functions consume No5 metadata entries from actual native scale, extent, edition and M_COVR coverage. The stack removes duplicate editions, sorts by scale and filters chart groups. The most detailed cell covering the viewport center selects the portrayal scale. Adjacent opened cells at that scale contribute to the same continuous frame. Without a center selection, opened cells can still render intersecting viewport geometry. This first slice does not implement full OpenCPN quilting of overlapping cells at different scales, its complete database index or automatic chart synchronization.

Android calls `No5ChartRenderer::renderGl`: the original `RenderAreaToGL` and `RenderObjectToGL` methods draw through the original S52 shaders into an EGL-owned GPU framebuffer sized for the Surface (bounded to 4096×1499). The compositor presents that GPU attachment with one uniform scale, preserving aspect ratio. `docs/PHASE0_SURFACE_TIMING.md` describes the coordinate mapping and timing boundaries. JNI has no full-frame CPU rendering, RGBA copying or chart-image texture upload.

The framebuffer is one continuous view. It is not a geographic tile. Original symbol atlases, HPGL symbol/pattern caches, sounding glyphs and cached text-string textures remain part of the original GLES portrayal. The font adapter can rasterize individual text/symbol resources on the CPU; this does not rasterize the entire chart. Text textures are retained across pan/zoom/rotation and invalidated when portrayal settings change. Vectors are evaluated again for each viewport, and text keeps its screen size.

`render` and `RgbaTarget` remain available for CPU reference tests. PNG/PPM readback is compiled into the host test target only. Android does not read the GPU chart back into CPU memory. There is no AVNav, ochartsng, HTML, WebView, MBTiles or persistent raster cache.

## Utility dependency and port repairs

`no5/port/no5_platform.hpp/.cpp` implement the minimum wx-compatible value, string, font, file and memory-DC call slots used by the original portrayal source. No wxWidgets library, wxApp, window, dialog, event loop, ChartCanvas or plugin-manager runtime is linked. Font metrics/rasterization use bundled DejaVu Sans through pinned stb_truetype; PNG atlases use pinned lodepng. This adapter's glyph metrics, font-weight handling, image scaling and raster primitives still require comparison with upstream OpenCPN images across a broader chart corpus. Identical upstream font/platform rasterization is not claimed.

Local port repairs are recorded in `no5/port/generated/PORT_MANIFEST.json`: aligned reads for packed S57/WKB/SENC fields, typed Striper deletion, initialized strip vertex bounds, defined fixed-point arithmetic, missing DRVAL2 initialization and direct viewport rotation. The GLES port also maps desktop-only capabilities, tracks texture dimensions without desktop texture queries, tessellates HPGL polygons through retained libtess2, checks shader failures and destroys/rebuilds GPU resources on Surface recreation. CPU points rotate directly; GLES points stay unrotated until the shader transform. Text remains upright and its recorded display bounds follow that transform. The facade resets sounding-font setup for each new memory DC, preserving identical glyphs between frames. No test sanitizer was disabled to hide those defects.

`docs/SOURCE_PROVENANCE.json` hashes every included verbatim upstream file. The port manifest records all retained regions and explicit edits from those originals. `scripts/regenerate_opencpn_port.py --check` verifies every generated source byte without modifying files; omitting `--check` regenerates it. Third-party/font/NDK header hashes and licenses are included.

## API and remaining gates

All requested coarse JNI operations are present. OpenCPN types remain within C++; Kotlin receives chart status, viewport and JSON feature results. Ownship, AIS, route and waypoint overlays are backend projections with development markers.

Nine host regressions cover continuous rendering, real palette/safety changes, actual rock attributes, rotation/offscreen behavior, vector zoom with constant text pixel dimensions, repeated-frame stability, exact SENC roundtrip, corrupt-cache rejection/rebuild, update gaps, original chart selection and a real NOAA harbour dataset. The Android default opens four adjacent Boston cells with sequential updates. Download sources, editions, updates and byte hashes are in `chart-engine/src/main/assets/charts/noaa/PROVENANCE.json`. The original NOAA agreement and ancillary text files are included. These tests do not replace a device smoke or an independent upstream reference-frame comparison. `completePortrayal` remains false to reflect the open acceptance boundary, even though the full CPU/GLES source dispatch is retained.

Official o-charts_pi/oexserverd integration and protected-device assignment remain the next chart-specific acceptance step specified by the prompt. No protected chart was accessed, decrypted or persisted. The foundation remains open until Android Surface/JNI/GLES, gestures and client recovery are observed on a real device or usable emulator.

Four additional offscreen GLES regressions exercise the actual production framebuffer target and original shaders: fixture areas/text, palette/safety/zoom/rotation, three context recreations and all 8202 Boston objects across four cells. They compare chart pixels to the retained CPU target with explicit tolerance, not to an independently running upstream application. Mesa llvmpipe executes those shaders in software; this proves the GLES drawing path and resource lifecycle, not Android-driver compatibility or hardware performance. Android native debug compilation uses `-O2`.
