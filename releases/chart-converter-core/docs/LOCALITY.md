# Explicit locality preparation

The packaged kernels can remove complete irrelevant parts and certified
owners from an existing source payload. This currently supports explicitly
selected existing L15 leaves, keeps at least one record, preserves the source
tree and never changes its scale or creates children. It appends active compact
arenas while retaining the original bytes, so a smaller disk file is not promised.

```sh
no-chart-converter plan-locality --source CHART.rx5 --expect-sha256 SOURCE_SHA256 \
  --tile 15 X Y --tile 15 OTHER_X OTHER_Y --output NEW_CANDIDATE.json
```

The candidate contains the source and immutable kernel identities plus each
canonical plan SHA256. Plans bind every original record, raw programme context,
complete render/query arena hashes, original part ordinals and element hashes,
geometric guards and compacted-buffer hashes. It is a review input and never an
approval or an applied chart. Whole-owner geometry uses a 64-source-pixel guard;
complete-part preparation uses 32 pixels, through destination level 29. Symbols,
text, conditionals and unsupported stroke forms do not qualify for omission.

The default `pure_ac_fill` command scope accepts only Kind3 solid `AC(...)`
fills in the two known drawing contexts. Lines, patterns, opaque metadata and
owners with other programmes remain unchanged. Broader `reviewed_kernels`
plans are proposals that require their own exact independent proofs; the CLI
does not select that scope. The command scope is bound into each plan hash and
must match the reviewed allowlist.

Every covered descendant translation must stay within the native signed32
projection domain. Conservative F64/F32/Qt interval bounds cover the full
translation range; four scalar endpoints per level check the actual rounding
expression. A doubtful or overflowing part or owner remains unchanged. Exactly
one terminal programme separator is accepted; internal or repeated empty tokens
remain unsupported. An opaque metadata context never qualifies as drawing code.
Preparation and application require a valid own plain-vector file header and
check the emitted single-file extent again after appending.

An independently reviewed allowlist uses
`no5-bound-scoped-locality-allowlist/1` with status
`APPROVED_FOR_SCOPED_PHYSICAL_A97_TEST`, the exact `source` and `kernels` objects
from the plan, and explicit rows containing:

- `tile`, `approved: true`, and the exact `planSHA256`;
- `visualSemanticDisposition` and `querySemanticDisposition`, both exactly
  `IDENTICAL_WITHIN_PROVED_SOURCE_DOMAIN`;
- `nativeSourceGateDisposition: UNCHANGED_SOURCE_IDS_AND_NATIVE_SCALE`;
- byte/SHA256 pins for independently reviewed `visualCertificate`,
  `admissionCertificate` and `querySemanticReport`.

There is no query-loss override, nearby-source substitution or automatic global
scope. Certificate hash equality binds the external review; it does not prove
that review's mathematics. All plans are recomputed before applying.

```sh
no-chart-converter apply-locality --source CHART.rx5 --allowlist REVIEWED.json \
  --expect-allowlist-sha256 ALLOWLIST_SHA256 --output NEW.rx5 --report NEW.json
```

Application checks the complete original-prefix inverse and active source tree,
kept typed elements including signed sounding depths, unchanged programmes/query
and resource addresses, and unchanged menu metadata. Both output paths must be
fresh. A candidate cannot be passed as its own approval. The report makes no
physical a97 or loading-time claim, and the ordinary country builder never runs
this command automatically.
